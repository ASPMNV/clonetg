# Архитектура проекта

## Обзор

Telegram Channel Translator - это асинхронное приложение на Python, которое автоматически копирует, переводит и публикует посты из одного Telegram канала в другой.

## Модули

### 1. main.py
**Назначение:** Точка входа приложения

**Функции:**
- Инициализация логирования
- Загрузка конфигурации
- Запуск основного сервиса
- Обработка сигналов завершения

### 2. bot_service.py
**Назначение:** Координация всех компонентов

**Функции:**
- Управление жизненным циклом приложения
- Основной цикл обработки постов
- Координация между компонентами
- Обработка ошибок

**Основной цикл:**
```python
while is_running:
    1. Получить новые сообщения (TelegramClient)
    2. Для каждого сообщения:
       a. Проверить в БД (Database)
       b. Обработать (PostProcessor)
       c. Отправить (TelegramClient)
       d. Сохранить в БД (Database)
    3. Ждать check_interval секунд
```

### 3. telegram_client.py
**Назначение:** Взаимодействие с Telegram API

**Функции:**
- Авторизация через Telethon
- Получение сообщений из канала
- Отправка сообщений в канал
- Работа с медиа файлами

**Зависимости:**
- Telethon

### 4. translator.py
**Назначение:** Перевод текста через Gemini API

**Функции:**
- Перевод текста на тайский язык
- Ротация API ключей
- Retry механизм
- Создание резюме репостов

**Алгоритм ротации:**
```python
1. Получить статистику использования ключей за последний час
2. Выбрать наименее используемый ключ
3. Попытаться перевести
4. Если ошибка - взять следующий ключ
5. Логировать использование в БД
```

**Зависимости:**
- google-generativeai

### 5. filter.py
**Назначение:** Фильтрация нежелательного контента

**Функции:**
- Определение спама по ключевым словам
- Фильтрация ссылок
- Удаление реферальных параметров
- Очистка текста

**Правила фильтрации:**
```python
Спам если:
- 2+ ключевых слова из spam_keywords
- Более 3 ссылок в посте
- Более 30% текста - эмодзи

Ссылки:
- Удалить если домен не в allowed_domains
- Удалить реферальные параметры (utm_*, ref, etc.)
```

### 6. post_processor.py
**Назначение:** Обработка и подготовка постов

**Функции:**
- Извлечение текста и медиа
- Обработка репостов
- Координация перевода и фильтрации
- Подготовка финального поста

**Процесс обработки:**
```python
1. Извлечь текст и медиа из сообщения
2. Проверить на спам (Filter)
3. Обработать репост (если есть)
4. Очистить ссылки (Filter)
5. Перевести текст (Translator)
6. Подготовить ProcessedPost
```

### 7. database.py
**Назначение:** Хранение состояния и статистики

**Функции:**
- Отслеживание обработанных постов
- Логирование использования API ключей
- Выбор оптимального ключа
- Статистика ошибок

**Схема БД:**
```sql
processed_posts:
- id (PK)
- source_channel
- source_message_id
- target_message_id
- processed_at
- status
- error_message

api_key_usage:
- id (PK)
- api_key_index
- used_at
- success
- error_message
```

### 8. config.py
**Назначение:** Управление конфигурацией

**Функции:**
- Загрузка из JSON
- Загрузка из переменных окружения
- Валидация через Pydantic
- Приоритет: env > config.json

## Поток данных

### Получение и обработка поста

```
1. TelegramClient.get_new_messages()
   ↓
2. Database.is_processed() - проверка дубликатов
   ↓
3. PostProcessor.process_message()
   ├─→ Filter.is_spam() - проверка спама
   ├─→ Filter.clean_text() - очистка ссылок
   └─→ Translator.translate() - перевод
       └─→ Database.get_least_used_key_index()
   ↓
4. TelegramClient.send_post()
   ↓
5. Database.mark_processed() - сохранение
```

### Ротация API ключей

```
1. Translator.translate() вызван
   ↓
2. Translator._get_next_key()
   ├─→ Database.get_least_used_key_index()
   └─→ Возврат ключа и индекса
   ↓
3. Попытка перевода
   ├─→ Успех: Database.log_api_usage(success=True)
   └─→ Ошибка: Database.log_api_usage(success=False)
       └─→ Retry с другим ключом
```

## Асинхронность

Приложение использует asyncio для неблокирующих операций:

```python
# Асинхронные операции
- Telegram API запросы
- Gemini API запросы
- База данных операции
- Основной цикл обработки

# Синхронные операции (через asyncio.to_thread)
- Gemini API (обернут в to_thread)
- Файловые операции
```

## Обработка ошибок

### Уровни обработки

1. **Уровень модуля**
   - Локальная обработка ошибок
   - Retry механизмы
   - Логирование

2. **Уровень сервиса**
   - Обработка критических ошибок
   - Graceful degradation
   - Уведомления

3. **Уровень приложения**
   - Глобальная обработка
   - Graceful shutdown
   - Cleanup

### Стратегии retry

```python
# Translator
- Max retries: 3
- Delay: 1 секунда
- Стратегия: Следующий API ключ

# TelegramClient
- Max retries: встроено в Telethon
- Exponential backoff

# Database
- Max retries: 3
- Delay: 0.5 секунды
```
